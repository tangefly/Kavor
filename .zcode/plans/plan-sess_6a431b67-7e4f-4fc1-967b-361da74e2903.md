# Kavor Decode Scaling Benchmark（decode 并发扩展曲线：Output tokens/s per GPU vs Tokens/s per User）

## Context

Kavor 目前只有 `benchs/bench.py` 一个粗粒度基准（单次全量提交、只有一个含 prefill 的总吞吐数字）。目标：decode 阶段专项评测之一——**decode_scaling**：扫描并发数 N，画 per-GPU 聚合吞吐 vs 单用户速度的扩展曲线（y 轴硬件效率，x 轴 ≈1/TPOT 用户体验），评估 continuous batching 批扩展能力，后续可与 vLLM 曲线叠加对比。

现状缺口：引擎 `SeqStats`（`sequence.py:18`）已有 `arrival/prefill_start/first_token_time`，但 `log_request_stats`（`llm_engine.py:138`）算完只打日志就丢弃；无 step 级计时；`generate()` 只返回 `{"text","token_ids"}`。

## 指标定义（写死在脚本里的语义）

- 每个 concurrency N 一个点，`--repeats` 次独立运行取均值±std
- **x 轴**：per-user decode tok/s = median over requests of `(completion-1)/(finish_time-first_token_time)`（含 prefill 干扰，反映真实体验；JSON 同时存 mean/p10/p90）
- **y 轴**：decode-only 聚合吞吐 = `Σ(decode step tokens)/Σ(decode step 时长)/TP`（只统计 `is_prefill=False` 的 step）
- 等长 input/output + `ignore_eos=True` + 全量提交 → prefill 优先调度使 decode 批近似恒定 = steady state
- 每个 (N, repeat) 独立种子生成全新随机 prompt，避免跨 run prefix cache 命中

- `step()`（关键：token 计数必须在 `postprocess` 之前抓，`scheduler.py:164` 会把 `num_scheduled_tokens` 清零）：
```python
def step(self):
    start = perf_counter()
    scheduled_seqs, is_prefill = self.scheduler.schedule()
    num_tokens = sum(seq.num_scheduled_tokens for seq in scheduled_seqs)
    forward = perf_counter()
    token_ids = self.model_runner.call("run", scheduled_seqs, is_prefill)
    forward_time = perf_counter() - forward
    if is_prefill:
        for seq in scheduled_seqs:
            seq.stats.first_token_time = perf_counter()
    self.scheduler.postprocess(scheduled_seqs, token_ids, is_prefill)
    now = perf_counter()
    self.step_stats.append({"ts": now, "prefill": is_prefill, "tokens": num_tokens,
                            "step_time": now - start, "forward_time": forward_time})
    for seq in scheduled_seqs:
        if seq.is_finished:
            seq.stats.finish_time = now
            self.request_stats.append({...})  # seq_id, request_id, 两长度, 4 个时间戳, prefix 命中
            self.log_request_stats(seq, now)
    outputs = [...]  # 原样返回
```

### 2. `benchs/decode_scaling.py`（新建，**单文件**：sweep + 画图）

命名统一为 decode_scaling：JSON 字段 `"benchmark": "decode_scaling"`、图题 `Decode Scaling Curve — <model> TP<n>`。

- argparse：`--model`（必填）、`--tp`、`--label`（默认 kavor，进 JSON/图例）、`--input-len` 512、`--output-len` 512、`--concurrency "1,2,4,8,16,32,64,128,256"`、`--repeats 3`、`--temperature 0.6`、`--enforce-eager`、`--gpu-memory-utilization`、`--max-num-seqs`、`--seed`、`--out-dir benchs/results`、`--no-plot`、`--plot-only <json...>`（从已有结果重画/多文件叠加，不重跑）
- sweep 流程：模型加载一次复用；小 warmup generate；读回生效配置（`config.max_num_seqs` 可能被 KV 缩减，`model_runner.py:348`），超出并发的点截断+warning；每 run 独立种子生成 N 条随机 prompt（token id 0–10000）→ `generate(..., use_tqdm=False)` → 取 `llm.step_stats`/`request_stats` → 算 x/y 摘要 + 一致性校验（Σ decode tokens == Σ(completion-1)）→ 打印单行；结束 `llm.exit()`
- JSON 输出 `{out_dir}/{时间戳}_{label}_{模型名}.json`：config 快照（GPU 名、torch 版本、生效 max_num_seqs）+ 每 run 完整 step_stats/request_stats + 摘要
- 画图函数 `plot_scaling(json_paths, out_png)` 与 bench 同文件：按 concurrency 聚合 repeats → (x 均值, y 均值) + xerr/yerr；`o-` 曲线，每 JSON 一条；`--annotate` 在点上标 N；轴标签 "Per-user decode throughput (tokens/s)" / "Decode throughput per GPU (tokens/s)"；存 PNG。matplotlib 在函数内 lazy import（`--no-plot` 时 sweep 完全不依赖它）
- 正常跑完 sweep 自动对本 run JSON 出图；`--plot-only` 可事后重画/合并
